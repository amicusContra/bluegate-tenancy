The military parallel: OSUT didn't just teach DaSean to fire a rifle.

### The Backbone Book: Learn Python the Hard Way (Zed Shaw, 5th Ed)

This book runs underneath everything else like a spine. It's not
about Python — it's about *precision*. Every exercise requires typing
code exactly, character by character. No copy-paste. No shortcuts.
Like scales on a piano: you're not making music yet, you're building
the muscle memory and exactness that lets you make music later.

What LPTHW teaches simultaneously:
- **Touch typing** — by forcing exact reproduction of code, it
  trains keyboard fluency faster than a typing tutor alone
- **Terminal work** — Appendix A is a full command line crash course
  (pwd, cd, ls, mkdir, rm, cp, mv) designed to be done in 1–2 days
- **Syntax discipline** — every missing colon, wrong indent, or
  misplaced quote produces an error. DaSean learns that computers
  are literal machines. They do exactly what you say, not what you mean.
- **Pseudocode thinking** — before writing code, describe what you
  want in plain English. Then translate. This is how professionals
  work: think first, then type.
- **Debugging** — the book deliberately introduces errors. DaSean
  learns to read error messages, trace problems, and fix them. This
  is the single most important skill in cybersecurity.

**How to use it**: 1–2 exercises per day, typed on the Linux machine.
60 exercises total = ~5–6 weeks at this pace, finishing right before
DSDT starts. Kevin is available for questions but DaSean works
through the errors himself first. The struggle is the learning.

Kevin has a physical copy from his MSDS prep. Hand it over.

## LAYER 1: FIRST PRINCIPLES — WHY BINARY, HOW COMPUTATION

This is where DaSean learns what a computer actually *is*. Not what
it does — what it IS.

### The Story (Kevin teaches this conversationally)

1. **Electricity is either on or off.** A switch. A light. A
   transistor. Two states. That's binary — not a design choice, but
   a physical reality. It's cheaper and more reliable to detect
   "on/off" than to detect ten different voltage levels.

2. **Binary is just counting with two digits.** Decimal uses 0–9.
   Binary uses 0–1. Same math, different base. 1010 in binary = 10
   in decimal. That's it. No magic.

3. **Boolean logic is decision-making with true/false.** AND, OR,
   NOT. Three operations. If the enemy is in range AND you have
   ammo, fire. If the radio is dead OR the backup is dead, you're
   dark. If the order is NOT to advance, you hold. DaSean already
   thinks in boolean logic — he just didn't know the name.

4. **Logic gates are physical boolean.** A transistor arrangement
   that takes inputs (on/off) and produces an output based on AND,
   OR, NOT rules. Stack enough gates and you get an adder — a
   circuit that does arithmetic. Stack enough adders and you get an
   ALU (Arithmetic Logic Unit). Put an ALU with memory and a clock
   and you get a CPU. That's a computer.

5. **Software is just instructions for the hardware.** Machine code
   is binary patterns the CPU understands. Assembly is human-readable
   machine code. High-level languages (Python, C) are human-readable
   instructions that get translated down to machine code. Every
   program DaSean has ever used on his phone was, at the bottom,
   electricity flowing through logic gates.

6. **Algorithms are recipes.** A set of steps to solve a problem.
   Sort a deck of cards? That's an algorithm. Find the fastest route
   on Uber? Algorithm. Search a database for a threat? Algorithm.
   DaSean follows algorithms every day — land nav, radio procedures,
   clearing a room. Computing just writes them down precisely enough
   for a machine to follow.

## KEVIN → DASEAN MENTORSHIP STRUCTURE

This isn't a classroom. It's an apprenticeship. Kevin is the master
craftsman; DaSean is the journeyman learning the trade.

### The Teaching Method

1. **Kevin demonstrates.** Shows DaSean something on the mesh or a
   machine. Explains what's happening and why.

2. **DaSean replicates.** Does the same thing on his own machine with
   Kevin watching.

3. **DaSean explains.** Teaches it back. If he can teach it, he owns
   it. If he can't explain it simply, he doesn't understand it yet.

4. **Kevin breaks it.** Introduces a fault, a misconfiguration, a
   problem. DaSean diagnoses and fixes it.

5. **DaSean documents it.** Writes up what he learned in his own
   notes. This builds the habit of documentation (CySA+ Domain 4)
   and creates a personal reference library.

### Weekly Schedule (Pre-Class)

| Day | Morning (30 min) | Evening (45–60 min) | Notes |
|-----|-----------------|--------------------|----|
| Mon | LPTHW exercise (1–2) on Linux machine | Crash Course CS videos (2 episodes) | Scales + theory |
| Tue | LPTHW exercise (1–2) on Linux machine | Khan Academy Python concepts | Scales + concepts |

**LPTHW is the constant.** Every morning, open the Linux terminal, type
the next exercise. No exceptions. Everything else rotates around it.

makes him irreplaceable.
